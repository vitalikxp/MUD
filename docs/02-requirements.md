# 02. Техническое задание

У каждого требования есть идентификатор (`FR-…`, `NFR-…`). Задачи, тесты и PR ссылаются на них.
Приоритет: **M** (must, нужно для MVP), **S** (should, желательно в MVP), **L** (later, после MVP).
В колонке «Веха» указано, где требование реализуется ([дорожная карта](10-roadmap.md)).

## 1. Роли

| Роль | Описание |
|---|---|
| Игрок | Управляет своим персонажем, подаёт заявки, видит общее состояние |
| Хост | Игрок, в чьём браузере работает Мастер (его ключ LLM). Управляет кампанией |
| Владелец кампании | Создатель кампании. Приглашает, исключает, меняет настройки. Обычно совпадает с хостом |
| ИИ-мастер (DM) | LLM + оркестратор. Ведёт повествование, вызывает инструменты движка |
| Автор контента | Пишет шаблоны сеттингов и модули правил в репозитории |

## 3. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-COST-1 | Эксплуатация стоит $0: GitHub Pages, Firebase Spark, Cloudflare Workers Free. Платные сервисы, карта в биллинге и Cloud Functions не используются |
| NFR-COST-2 | Кооп-группа из 5 человек, играющая 4 часа в день, тратит не больше 20% дневных лимитов Firestore ([бюджет](06-data-model.md#бюджет-бесплатного-тарифа)) |
| NFR-LIFE-1 | Долговечность: без релея и без Firebase соло-режим с CORS-дружественным провайдером продолжает работать |
| NFR-LIFE-2 | Код relay лежит в репозитории, любой может задеплоить свою копию. URL relay настраивается у клиента |
| NFR-LIFE-3 | Зависимостей минимум, версии зафиксированы lock-файлом, Dependabot включён только для security-обновлений |
| NFR-LIFE-4 | Экспорт JSON содержит всё для восстановления кампании. Формат версионирован, есть миграции |
| NFR-SEC-1 | Ключ LLM никогда не передаётся никуда, кроме выбранного провайдера (через relay или напрямую) |
| NFR-SEC-2 | Relay принимает запросы только с разрешённых Origin и только к хостам из allowlist. Он не логирует тела запросов и заголовок Authorization |
| NFR-SEC-3 | Правила Firestore и RTDB: читают только участники кампании, события пишет только действующий хост, заявку пишет только её автор. Правила покрыты тестами на эмуляторе |
| NFR-SEC-4 | Строгий CSP: `connect-src` содержит только Firebase, relay и адреса провайдеров, заданные пользователем. Текст от LLM не вставляется как HTML |
| NFR-SEC-5 | Данные с `visibility: "dm"` не попадают в Firestore и RTDB открытым текстом. Тест правил: не-хост не читает `secrets/*` |
| NFR-PERF-1 | Первая отрисовка меньше 2 с на 4G. JS без шрифтов меньше 300 КБ gzip (Firebase SDK подгружается лениво, только для облачных кампаний) |
| NFR-PERF-2 | Перерисовка карты 120×60 при движении фишки занимает меньше 16 мс на среднем ноутбуке |
| NFR-PERF-3 | Первый токен повествования приходит через 3 с после закрытия раунда (без учёта задержки модели) |
| NFR-A11Y-1 | Управление полностью доступно с клавиатуры, фокус виден. Символы рамок скрыты от скринридеров (`aria-hidden`), хроника объявляется через `aria-live="polite"` |
| NFR-A11Y-2 | Палитра «высокий контраст» есть всегда. Смена палитры Мастером её не перебивает |
| NFR-A11Y-3 | Учитывается `prefers-reduced-motion`: без анимаций переходов палитры и печатающего текста |
| NFR-I18N-1 | Все строки UI лежат в словарях `ru` и `en`. CI проверяет, что ключи совпадают |
| NFR-REL-1 | Ход атомарен: события хода коммитятся одной пачкой после успешного завершения конвейера Мастера |
| NFR-REL-2 | Запросы к LLM повторяются с экспоненциальной задержкой при 429/5xx. Ход можно отменить |
| NFR-LEGAL-1 | Лицензии: код — 0BSD, контент — CC0 1.0, модуль OpenD6 — OGL 1.0a с полным текстом лицензии и Section 15. Сторонние шрифты — с атрибуцией в `NOTICE.md` ([ADR-0012](adr/0012-licensing.md), [ADR-0013](adr/0013-code-license-0bsd.md)) |
| NFR-OBS-1 | Режим отладки Мастера (для хоста): собранный контекст, вызовы инструментов, токены, время. Хранится только локально |
