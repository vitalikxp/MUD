## Ключевые потоки

### Ход (соло или кооп, у хоста)

1. Игроки создают **заявки** (`intent`). В соло заявка сразу закрывает раунд.
2. Хост закрывает раунд, и оркестратор собирает **контекст** ([04](04-ai-dm.md#сборка-контекста)).
3. LLM отвечает: вызовы инструментов → движок выполняет их **на черновике состояния** и возвращает результаты модели → … → итоговый текст.
4. Пока идёт генерация, текст стримится: локально сразу, в кооп через RTDB `stream/{cid}` раз в ~250 мс.
5. Конвейер завершился успешно, и вся пачка событий хода (броски, изменения, повествование) пишется **одним коммитом**.
6. Проекции (персонажи, сцена, карта, лор) пересчитываются редьюсером и сохраняются: локально или в Firestore батчем.
7. После хода асинхронно запускается «обслуживание»: сводки, проверка лора. Оно создаёт отдельный коммит.

Если на любом шаге до пункта 5 произошла ошибка, черновик выбрасывается и состояние не меняется ([NFR-REL-1](02-requirements.md)).

### Бытовое действие игрока (без LLM)

Экипировать меч: UI создаёт заявку `ui.action` → движок у хоста валидирует её правилами модуля → событие → коммит.
Если действие не зависит от чужого состояния, в соло применяется сразу, в кооп после подтверждения хостом (обычно меньше секунды).

### Загрузка кампании

Читается документ кампании и проекции `state/*`. Хронику видно из последних N коммитов, остальное подгружается при прокрутке.
Полный журнал читается только при экспорте, откате и миграции.

## Хранилище: два адаптера

```ts
interface StorageAdapter {
  loadCampaign(id): Promise<CampaignSnapshot>;
  commit(c: Commit, projections: ProjectionPatch): Promise<void>; // атомарно
  subscribe(id, handlers): Unsubscribe; // коммиты, проекции, заявки
  submitIntent(i: Intent): Promise<void>;
  // ...
}
```
- `LocalAdapter`: IndexedDB. Нужен для соло, работает без аккаунта и без сети (кроме LLM).
- `FirebaseAdapter`: Firestore + RTDB. Нужен для кооп-кампаний, SDK Firebase грузится динамическим `import()`.

## Деплой

| Что | Куда | Как |
|---|---|---|
| SPA | GitHub Pages, домен `swrd.ru` (`public/CNAME`) | GitHub Actions: `pnpm i --frozen-lockfile && pnpm test && pnpm build`, для SPA-маршрутов копируется `404.html` |
| Правила Firebase | Firebase project | `pnpm firebase:deploy-rules` вручную (секреты CI не держим) |
| Relay | Cloudflare Workers | `pnpm relay:deploy` (wrangler) вручную. Отдельная инструкция для форков |
| Конфиг Firebase | в сборке | `VITE_FIREBASE_*` из GitHub Secrets. Ключи публичные по природе, защита держится на правилах |

### Домен и репозиторий

- Репозиторий: `git@github.com:vitalikxp/swrd.ru.git`, основная ветка `master` (деплой по push).
- Домен: `https://swrd.ru`. Сайт живёт в корне, поэтому в Vite `base: '/'`. В `public/CNAME` одна строка `swrd.ru`.
- DNS (проверено 2026-09-28):
  - `swrd.ru` A → `185.199.108–111.153`, AAAA → `2606:50c0:8000–8003::153`. Уже настроено верно.
  - `www.swrd.ru` CNAME → сейчас `swrd-ru.github.io` (**другой аккаунт GitHub**). Нужно поменять на `vitalikxp.github.io`,
    иначе `www` не будет перенаправлять на сайт.
- В настройках репозитория (Settings → Pages): Source = GitHub Actions, Custom domain = `swrd.ru`, Enforce HTTPS.
  Рекомендуется подтвердить домен в настройках аккаунта (Settings → Pages → Verified domains), чтобы его не мог занять чужой репозиторий.
- Firebase Auth → Authorized domains: `swrd.ru` (+ `localhost`).
- Relay: разрешённый Origin `https://swrd.ru`.

## Технологии

| Задача | Выбор | Причина |
|---|---|---|
| Язык | TypeScript strict | типы событий и схем, агентам проще |
| UI | Preact + `@preact/signals` | ~4 КБ вместо ~45 КБ у React, точечные обновления без перерисовки дерева, меньше зависимостей ([ADR-0008](adr/0008-dom-char-grid-preact.md)) |
| Схемы | Zod | валидация аргументов tool calls, контента, импорта; JSON Schema для LLM через `zod-to-json-schema` или `z.toJSONSchema` |
| Сборка | Vite | стандарт |
| Типы и линтер | TypeScript 7 (`tsc --noEmit`), oxlint | `typescript-eslint` несовместим с TS 7 ([ADR-0019](adr/0019-typescript7-oxlint-font-source.md)) |
| Тесты | Vitest, Playwright, `@firebase/rules-unit-testing` | |
| Локальное хранилище | IndexedDB через `idb` | маленькая обёртка |
| i18n | собственный типизированный словарь (без i18next) | меньше зависимостей, ключи проверяются типами |
| Стили | CSS-переменные + CSS Modules, без Tailwind | TUI живёт в единицах `ch`/ячейках, утилитарный CSS мало что даёт |
