# 11. Качество и эксплуатация

## Пирамида тестов

| Уровень | Что | Инструмент | Где запускается |
|---|---|---|---|
| Unit | `engine/`, `rules/`, парсер кубов, генераторы карт, редьюсер, ретривер, сборка контекста, `wrapToWidth`, контраст палитр | Vitest | CI, локально |
| Property | Детерминизм: одинаковые seed и события дают одинаковое состояние. Пересчёт проекций из журнала совпадает с сохранёнными | Vitest + fast-check (опц.) | CI |
| Инструменты Мастера | Каждый инструмент: валидные и невалидные аргументы, события, результат для LLM | Vitest | CI |
| Оркестратор | Tool-loop на **mock-LLM** (скриптованные ответы и фикстуры): успешный ход, ошибка валидации, превышение итераций, обрыв стрима → откат | Vitest | CI |
| Контракт LLM | Разбор SSE и tool-calls на записанных ответах реальных провайдеров (`src/llm/__fixtures__/`) | Vitest | CI |
| Правила безопасности | Кто может читать и писать каждую коллекцию, аренда хоста, заявки | `@firebase/rules-unit-testing` + эмулятор | CI |
| E2E | Соло-сценарий, кооп из 3 контекстов, захват хоста, мобильная раскладка | Playwright + mock-LLM + эмулятор | CI (кроме тяжёлых), локально |
| Evals Мастера | Поведение реальной модели на сценариях ([04](04-ai-dm.md#evals)) | `pnpm eval:dm` | локально, с ключом |

Mock-LLM: `src/llm/mock.ts` реализует тот же интерфейс, что и клиент, и в dev-сборке включается флагом `?mockLlm=scenario-name`.

## CI (GitHub Actions)

Файл: `.github/workflows/deploy.yml`. Запускается на push в `master`, на PR и вручную.

```
check:  pnpm install --frozen-lockfile → typecheck → lint → test → docs:check
e2e:    playwright install chromium → test:e2e (desktop 1280 + mobile 390); при падении — трейсы в артефактах
build:  (только master, после check и e2e) pnpm build → upload-pages-artifact
deploy: deploy-pages → https://mud.vitalik.dev
```
- Во всех job checkout — sparse, без `ref/OpenD6/*.pdf` и `ref/OpenD6/text/` (~360 МБ, [ADR-0014](adr/0014-reference-books-in-git.md)).
  Markdown в `ref/OpenD6/` остаётся: на него ссылается документация.
- Позже добавятся: `test:rules` на эмуляторе Firebase (M3), mock-LLM в e2e (M1).
- Секреты: только `VITE_FIREBASE_*` (с M3). Ключей LLM в CI нет, evals в CI не запускаются.

## Relay (Cloudflare Worker)

- `POST /v1/chat/completions`, `/v1/responses` и `GET /v1/models` (список моделей для окна выбора) → `https://<upstream>/…`. Пропускаются заголовки `Authorization`, `x-opencode-session`; `User-Agent` ставит сам relay. Подробности и деплой: [relay/README.md](../relay/README.md). Upstream задаётся заголовком `X-Upstream` и проверяется по **allowlist**
  (`opencode.ai`, `openrouter.ai`, `generativelanguage.googleapis.com`, …). Список в `relay/allowlist.ts`.
- CORS: `Access-Control-Allow-Origin` только для разрешённых Origin (`https://mud.vitalik.dev`, `http://localhost:*`; форки задают свой список переменной окружения).
- Заголовок `Authorization` передаётся как есть. **Тела, заголовки и ответы не логируются.**
- Стриминг: тело ответа upstream проксируется потоком. Ожидание сети не расходует лимит CPU в 10 мс.
- Лимит бесплатного тарифа — 100K запросов в сутки на весь relay. Один ход занимает 1–12 запросов. Если лимит станет проблемой, пользователи смогут задеплоить свой relay (инструкция в `relay/README.md`).
- Для OpenCode Go обязательны заголовки `x-opencode-session` (ID кампании; без него ответ `400 MissingSessionID`) и уникальный `User-Agent` (в браузере его выставляет relay: `mud-relay/<версия>`) ([ADR-0018](adr/0018-reasoning-effort-and-go-headers.md)).
  OpenCode Go — пресет по умолчанию. Риск ограничения ключа по условиям сервиса владелец принял (Q6), в UI есть предупреждение.

## Долговечность («проект живёт без автора»)

| Риск | Защита |
|---|---|
| Relay проекта упал или превысил лимит | URL relay настраивается у клиента; есть прямой режим для CORS-дружественных провайдеров; код relay деплоится за 5 минут |
| Провайдер LLM закрылся, поменял условия, забанил | Провайдер-агностичный клиент, пресеты правятся в настройках без пересборки (свой base URL) |
| Firebase-проект удалён или заблокирован | Соло-режим целиком локальный; экспорт JSON; README «как поднять свой Firebase» и конфиг через `.env` |
| Устарели зависимости | Минимум зависимостей, lock-файл, отсутствие SSR и серверного кода; сборка воспроизводима на Node LTS |
| GitHub Pages | Сборка — обычная статика, переносится на любой статический хостинг (Cloudflare Pages, Netlify) без изменений |
| Модели изменились, Мастер стал хуже | `eval:dm` фиксирует ожидания, промпты версионированы |

## Наблюдаемость

Серверной телеметрии нет. Отладочные данные хранятся только у хоста локально ([04](04-ai-dm.md#отладка-мастера-для-хоста)).
Кнопка «Скопировать отчёт об ошибке» собирает версию, последние ошибки и (по согласию) отладку хода **без ключа**.
