# 07. UI / TUI

## Образ

Norton Commander и DOS-игры 90-х: весь экран — сетка символов, панели в рамках из псевдографики, внизу строка F-клавиш,
курсор-блок в строке ввода. Фон по умолчанию тёмный, терминальный. Мастер «красит» экран палитрой под сцену.

## Сетка символов

- UI раскладывается в **ячейках**: `cols × rows`. Ширина ячейки измеряется по реальному шрифту (`measureText("█")`), высота равна `line-height`.
- Размер сетки вычисляется из окна: `cols = floor(W / cellW)`, `rows = floor(H / cellH)`. Остаток по краям заполняется фоном.
- Для пиксельных шрифтов масштаб целочисленный (×1, ×2), чтобы не было мыла. Автомасштаб — наибольший, при котором помещается «комфортная» сетка 160×50 (вдвое больше минимума): 16 CSS px — обычный размер текста, поэтому ноутбуки и мониторы получают ×1, 4K-ТВ — ×2. Ручной выбор масштаба — FR-UI-7.
- **Минимум десктоп-раскладки**: 80×25. Меньше 80 колонок включает мобильную раскладку.
- Позиции и размеры панелей задаются только в ячейках. Внутри панели текст выводится строками точной ширины (`white-space: pre`).

### Рендеринг ([ADR-0008](adr/0008-dom-char-grid-preact.md))

- Панель рендерит массив строк, каждая строка — массив **цветовых отрезков** `{ text, fg, bg, attrs }` → `<span>`.
  Не по `<span>` на ячейку: это слишком много DOM-узлов.
- Карта (самая «горячая» панель) рендерит только изменившиеся строки (`memo` по хэшу строки, подписка на сигналы только своих строк).
- Рамки строит утилита `frame(w, h, style, title?, active?)`. Символы рамки получают `aria-hidden="true"`.
- Весь текст в TUI проходит через `wrapToWidth(text, width)`, который учитывает переносы слов и кириллицу.
  Широкие символы (эмодзи, CJK) заменяются на `?`, потому что они ломают сетку.

## Рамки

| Состояние | Стиль | Символы |
|---|---|---|
| Неактивная панель | одинарная | `┌─┐│└┘├┤┬┴┼` |
| Активная (в фокусе) | двойная | `╔═╗║╚╝╠╣╦╩╬` |
| Диалог | двойная + тень | тень рисуется `░` или затемнением фона на 1 ячейку справа и снизу |
| Разделитель внутри | одинарная | `├───┤` |

Заголовок панели вписывается в верхнюю рамку: `╔═[ Хроника ]══════╗`. Полосы ресурсов: `█▓▒░`, например `Тело ██████░░░░ 22/31`.

## Шрифт

Один: **PxPlus IBM VGA 9x16** (The Ultimate Oldschool PC Font Pack v2.2, VileR, CC BY-SA 4.0), self-hosted в `public/fonts/pxplus-ibm-vga/` (без Google Fonts, это NFR-LIFE).
Переключения шрифтов нет ([ADR-0020](adr/0020-single-font.md)): рамки, шкала масштаба и сетка выверены под его метрики (ячейка 9×16). Крупнее текст делает зум браузера.

Что требуется от шрифта: моноширинность, кириллица, box-drawing, блочные элементы (`█▓▒░▀▄▌▐`), стрелки, `·•♦♥♣♠`. Маркер броска — `♦` (в PxPlus нет `◆`, [ADR-0019](adr/0019-typescript7-oxlint-font-source.md)).

На тестовой странице `/dev/glyphs` видно все нужные символы в сетке, рамки смыкаются без зазоров. Атрибуция шрифта — в `NOTICE.md`.

## Палитры

Палитра — это набор **семантических токенов**, а не «16 цветов EGA». Компоненты используют только токены.

| Токен | Назначение |
|---|---|
| `bg`, `bgAlt`, `bgPanel` | фон экрана, чередование строк, фон панели |
| `fg`, `fgDim`, `fgBright` | основной, приглушённый, выделенный текст |
| `frame`, `frameActive`, `title` | рамки и заголовки |
| `accent`, `accent2` | акценты, ссылки на лор, варианты действий |
| `dm`, `player`, `ooc`, `system` | цвета реплик в хронике |
| `success`, `failure`, `crit`, `fumble` | результаты бросков |
| `hp`, `hpLow`, `mana` | полосы ресурсов |
| `danger`, `warning`, `info`, `magic` | состояния и предупреждения |
| `selBg`, `selFg`, `cursor` | выделение и курсор |
| `mapFloor`, `mapWall`, `mapWater`, `mapFog`, `mapSeen`, `mapToken`, `mapEnemy`, `mapAlly` | карта |

Встроенные палитры (`content/palettes/*.json`): каждая с названием RU/EN и описанием «когда уместна». Это описание уходит в контекст Мастера.

| id | Настроение | Мастер использует для |
|---|---|---|
| `terminal` | чёрный фон, светло-серый текст, циановые акценты | по умолчанию |
| `nc-blue` | синий фон, голубые рамки, жёлтые акценты (Norton Commander) | город, безопасное место, меню |
| `amber` | янтарный монохром | воспоминания, документы, записки |
| `phosphor` | зелёный монохром | технологии, древние машины, sci-fi |
| `torchlight` | тёплые тёмные тона, оранжевый | подземелье, пещеры, ночь у костра |
| `crimson` | тёмно-красный | бой, кровь, тревога |
| `frost` | холодные синие | зима, смерть, отчуждение |
| `fey` | фиолетовый и розовый | магия, сон, фейри |
| `void` | почти обесцвеченная | ужас, безумие, пустота |
| `sepia` | сепия | флешбеки, пролог |
| `high-contrast` | белый на чёрном, максимальный контраст | доступность, **Мастеру недоступна** |

Правила смены:
- `set_palette` меняет палитру через CSS-переменные, переход 400 мс (без него, если `prefers-reduced-motion`).
- Не чаще одного раза за ход. Палитра — часть `state/core`, при загрузке восстанавливается.
- Настройки игрока: «Разрешить Мастеру менять палитру» (вкл) и «Моя палитра» (фиксированная, перекрывает Мастера).
- Контраст `fg/bg` ≥ 7:1 и `fgDim/bg` ≥ 4.5:1 проверяется тестом для каждой палитры.

## Раскладки

### Десктоп (≥ 80 колонок)

```
╔═[ Хроника ]══════════════════════════════════════════════════════════════════════╗
║ Сырой воздух пахнет воском и гнилью. У алтаря кто-то оставил цветы.              ║
║                                                                                  ║
║ Вы> осторожно поднимаю монету кинжалом                                           ║
║                                                                                  ║
║ Под лепестками блестит монета с чужим гербом. Что дальше?                        ║
╟──────────────────────────────────────────────────────────────────────────────────╢
║ Вы> █                                                                            ║
╚══════════════════════════════════════════════════════════════════════════════════╝
 ● готов · muse-spark-1.3-contributor · ↑412 ↓474 ток. · 7,9 с        Терминал · RU 
 1Помощь  4LLM  7Состояние  8Палитра  9Язык                                            
```
- **Хроника** — во всю ширину, с полосой прокрутки и строкой ввода. В кампании справа (экран ≥ 110 колонок) стоит колонка в 40 колонок с панелями «Персонаж» (здоровье и очки, ниже характеристики, навыки, особенности; колесо листает) и «Вещи» (деньги и предметы: ● надето с названием слота, ○ в сумке; у выбранного предмета внизу урон, броня, заряды). Панель «Вещи» интерактивна: **F3** переводит на неё фокус (повторно — назад в строку ввода), ↑↓ выбирают предмет, **Enter** (или клик, тап) открывает меню действий, Esc возвращает фокус. Панели живые: перерисовываются по журналу после каждого хода. Под карту, отряд и лор колонка зарезервирована; в чате без кампании её нет.
- **Палитра, состояние, справка и настройки LLM — всплывающие окна** (F8, F7, F1, F4), а не панели: они не занимают места, которое нужно игре. Окно палитры: ↑/↓ показывают палитру сразу (предпросмотр), Enter выбирает, Esc возвращает прежнюю.
- **Строка состояния** (над F-клавишами): слева индикатор LLM, справа палитра и язык.
  - `● готов · <модель> · ↑<вход> ↓<выход> ток. · <время>` — итоги последнего ответа;
  - `● Мастер отвечает…` — идёт запрос;
  - `○ LLM не настроен: <чего не хватает>` — нет ключа, relay или согласия;
  - `× ошибка: <причина>` — последний запрос не удался (проходит после следующего удачного).
  На узком экране правая часть отбрасывается, а левая обрезается с «…» (`layoutStatus`).
- Значки состояния берутся из шрифта: `●`, `○`, `×` есть, а `✗`, `⚠`, `◆`, `◌` — нет (проверено `fc-query`), их не использовать.

### Мобильная (< 80 колонок)

```
┌─[ Хроника ]──────────────────┐
│ Сырой воздух пахнет воском…  │
│ ♦ Поиск 4D+1 = 21 ≥ 15 ✓     │
│ [1] Взять монету             │
│ [2] Осмотреть алтарь         │
├──────────────────────────────┤
│ > _                          │
└──────────────────────────────┘
 Палитра  Состояние  LLM  ≡
```
- Одна панель на экран, снизу вкладки (тапабельные, высота не меньше 2 строк или 44 px).
- Строка ввода прилипает к клавиатуре (`visualViewport`).
- Карта панорамируется жестами, фишка двигается тапом по клетке и подтверждением.

## Откат и повтор хода

Команды строки ввода в кампании (F-клавиш и вкладок для них нет):
- **`/undo`** отменяет последний действующий ход Мастера или бытовое действие с вещами; повторяется, пока есть что отменять, до создания героя (его отменить нельзя). Повтора (redo) нет. Лента перестраивается по журналу, под ней системная строка «Отменён последний ход Мастера.». Пока Мастер отвечает, недоступно.
- **`/retry`** — ход заново. Если последний ход не удался или прерван (ошибка провайдера, Esc), отправляется та же реплика без отката. Иначе последний ход Мастера откатывается и его реплика (или открытие игры) уходит снова. Кубы те же (`undoLastAction` возвращает генератор на начало хода), меняется текст Мастера и вызовы инструментов. Если последним было бытовое действие, повторять нечего: сообщение предлагает `/undo`. Без настроенной LLM откат не выполняется.
- Мастер после отката видит только оставшуюся историю (`effectiveCommits`): отменённая реплика и ответ из контекста исчезают.

## Бытовые действия с вещами

Меню действий (`ItemActionDialog`) открывается из панели «Вещи» и окна F3 по Enter (клик и тап тоже). Пункты: **Надеть / взять** или **Снять**, **Использовать**, **Выбросить** (у стопки — «Выбросить 1» и «Выбросить все (N)»), **Отмена**.
- Надеть, снять, выбросить выполняются мгновенно, без Мастера: `inventoryAction` (`src/app/inventory.ts`) → правила модуля (`rules.equipment`) → коммит `ui_action` с событиями `item.slot` / `item.removed` и записью `note`. В хронике появляется строка `· Ирма берёт «Кинжал» в руку.` системным цветом. Отклонённое правилом действие в журнал не попадает, причина показывается предупреждением.
- Пока Мастер отвечает, действия недоступны («Мастер ещё отвечает»): иначе они гонялись бы с коммитом хода.
- **Использовать** не действие движка: это реплика игрока «Использую «X».» (на языке кампании) в ход Мастера; эффект решает он инструментами (`heal`, `take_item` и т. д.).
- Мастер узнаёт о бытовых действиях из контекста следующего хода: блок «Player actions since your last turn (already applied to the state…)» (`pendingPlayerNotes`), а надетое видно и в листе героя.

## Markdown в ответах Мастера

Текст Мастера (повествование в хронике, ответ чернового чата) разбирается как Markdown в `src/ui/tui/markdown.ts` (`markdownLines(text, width, fg)`, чистая функция). Реплики игрока, системные сообщения и ошибки показываются как есть (`Entry.md` есть только у текста Мастера). Разметка превращается в стиль ячеек, а не в символы:

| Markdown | В сетке |
|---|---|
| `# Заголовок` | цвет `accent`, без `#` |
| `**жирный**`, `*курсив*` / `_курсив_`, `***оба***`, `~~зачёркнутый~~` | цветом токенов палитры: жирный — `fgBright`, курсив — `accent2`, оба — `accent`; зачёркнутый — `fgDim` с чертой. Синтезированного начертания нет (шрифт один, пиксельный); вложенность работает |
| `` `код` `` | цвет `accent` на фоне `bgAlt`, разметка внутри не разбирается |
| блок ``` | строки как есть (жёсткий перенос по ширине), тот же цвет и фон; незакрытый блок идёт до конца |
| `- пункт`, `1. пункт`, вложенные | `• `/номер и висячий отступ при переносе |
| `> цитата` | `│ ` и приглушённый цвет |
| `[текст](url)` | подчёркнутый текст, адрес приглушённо в скобках (если он отличен от текста) |
| `---` | линия во всю ширину |
| `\*` | экранирование |

Незакрытая разметка остаётся буквальной: пока ответ стримится, звёздочка без пары не ломает вид. Таблицы, HTML и картинки не поддерживаются и показываются как текст. `snake_case` и `2 * 3 * 4` курсивом не становятся. Свойства `underline` и `strike` есть в `Segment`; цвета берутся только из токенов палитры. В монохромных палитрах (`amber`, `phosphor`, `void`) курсив (`accent2`) от обычного текста отличается слабо: так задан токен палитры.

## Прокрутка

Любой текст, который может не поместиться, показывается через `ScrollText` (`src/ui/tui/ScrollText.tsx`), а длинные списки — через `Menu`:
- справа появляется полоса прокрутки (`░` дорожка, `█` ползунок); текст при этом переносится заново на ширину без одного столбца (`layoutScroll`);
- колесо мыши и жест пальцем листают везде; в `Menu` колесо сдвигает выбор;
- клавиши: в окнах справки, состояния и листа героя (поле в фокусе) — ↑/↓, PgUp/PgDn, Home/End; там, где фокус на списке или форме (описание шаблона, заметки настроек), PgUp/PgDn листают текст, а не список;
- окна и экраны, которым нужно листать, используют `ScrollText`: справка (F1), состояние (F7), «Персонаж» (F2), «Вещи» (F3), настройки LLM (заметки под формой), создание героя (описание шаблона), хроника (собственная реализация).

## Титульный экран, создание героя, игра (M1.4)

Адреса: `/` — титульный экран, `/game/<id>` — кампания, `/dev/chat` — черновой чат с моделью без кампании (наследие M0), `/dev/glyphs`.

- **Титульный экран** (`TitleScreen`): панель «{имя проекта} · Кампании» (имя из `brand.json`), список (название, вариант, «ходов: N» или «герой не создан») и пункт «+ Новая кампания».
  Enter — открыть, **Del** — удалить (окно подтверждения, курсор сразу на «Отмена»), F3 — новая (название, вариант правил). На телефоне вместо F-клавиш вкладки «Новая / Удалить / Палитра / LLM / ≡».
- **Создание героя** (`CreationScreen`, открывается, пока у кампании фаза `creation`): шаг «шаблон» (список + описание) → «имя» → «навыки»:
  список навыков шаблона, ←/→ или клик меняют очки на один пункт, PgUp/PgDn — на кубик; сверху остаток очков, снизу пункт «[ Создать героя ]» и F10. Esc — шаг назад, с первого шага — к списку кампаний.
  Игра начинается, когда герой записан в журнал (коммит `system` с `entity.created`, фаза → `play`).
- Лист героя: обычные записи — «название значение подсказка» в одну строку, особенности (преимущества, недостатки, способности) — в одну колонку: строка «название · вид», под ней описание абзацем с отступом.
- **Настройки LLM → «Модель»** (Enter): окно выбора модели из всего списка провайдера, проверенные первыми и цветом (`●` зелёный — рекомендуем, жёлтый — с оговорками, `×` красный — не работает, `○` — не проверена), внизу заметка к выбранной, справа полоса прокрутки. Подробности — [04](04-ai-dm.md#проверенные-модели-и-выбор-модели).
- **Игра** (`/game/<id>`): та же раскладка, что у чата; F2 — «Персонаж» (лист героя, окно с прокруткой), F3 — «Вещи» (на широком экране фокус на панель справа, на узком окно с тем же списком), F10 — к списку кампаний. Реплики уходят в оркестратор Мастера (`playTurn` → `takeTurn`), лента строится по журналу кампании (`src/app/chronicleLog.ts`): реплика игрока, повествование, открытые броски (`♦ …`, зелёным/красным по исходу), варианты действий последнего хода. После перезагрузки лента та же. `/start` — Мастер открывает игру; Esc прерывает ход, уход с экрана кампании тоже; неудавшийся ход в журнал не попадает.
- Окно настроек первого запуска остаётся единственным на экране на любом адресе, пока настройки не заданы.

Позже, с играми: F5 и F6 остаются за браузером (перезагрузка, адресная строка), поэтому панели игры (лист, вещи, карта, лор, журнал) получат другие клавиши и Alt-варианты; Ctrl+Enter — «Готов» в кооп-раунде.

## Хроника: представление событий

| Событие | Вид |
|---|---|
| `narration` | текст цветом `dm`, реплики NPC в `*...*` цветом `accent` |
| `intent` | `Имя> текст` цветом `player` |
| `roll` | `♦ Причина КОД: кубы W-цепочка +пипы = итог ≥ сложность ✓`, например `♦ Поиск 4D+1: 3 5 2 W6→4 +1 = 21 ≥ 15 ✓`. Цвета `success`/`failure`; взрыв Wild Die — `crit`, осложнение (1 на Wild Die) — `fumble` и пометка `⚠ осложнение`. Потраченные CP/FP показываются как `+CP`/`FP×2` |
| `item.*`, `entity.patched` (здоровье) | компактная системная строка `system`: `+ Монета с гербом → Ирма`, `Борк −5 Тело (17/34) · Ранен −1D` |
| `palette.set`, `scene.set` | разделитель `─── Крипта · ночь ───` |
| `turn.ended` | варианты `[1] … [2] …` |
| `revert` | откаченные события зачёркнуты, приглушённые |

## Хроника: прокрутка, отступы и ожидание

- **Отступы**: между записями хроники пустая строка. Реплика игрока, пустая строка, ответ Мастера.
- **Прокрутка**: PgUp/PgDn (страница минус строка), колесо мыши (3 строки), жест пальцем на телефоне. Справа столбец полосы прокрутки (`░` дорожка, `█` ползунок), она видна, только когда текст не помещается;
  столбец под неё зарезервирован всегда, чтобы перенос строк не менялся при её появлении. Полоса скрыта от скринридеров.
- **Следование**: внизу лента идёт за новым текстом (в том числе за стримом ответа). Если игрок прокрутил вверх, видимый кусок остаётся на месте, пока текст растёт снизу. Своя реплика возвращает к концу.
- **Ожидание ответа**: пока Мастер думает, в ленте строка `Мастер думает [░░▒█▒░░░░░]` — блок с «шлейфом» бегает туда-обратно (кадр каждые 120 мс). Первая порция ответа заменяет её.
  При `prefers-reduced-motion` кадр не меняется. Строка скрыта от скринридеров; вместо неё `role="status"` объявляет «Мастер думает…» один раз.
- Логика вынесена в чистые функции `src/ui/tui/scroll.ts` (сдвиг, ползунок, кадр анимации) и покрыта тестами.

## Курсор мыши

Блок размером в клетку, привязанный к сетке, как курсор мыши в текстовом режиме DOS. Цвета под ним инвертируются (`mix-blend-mode: difference` по белой заливке),
поэтому он читается на любой палитре без отдельных картинок. Зажатая кнопка — нижняя половина клетки.

- Системный курсор скрывается только после первого движения мыши по сетке и возвращается, когда мышь уходит за её край или из окна: без JS и на сенсорных экранах остаётся обычный.
- Показывается только для `pointerType: mouse` при `(pointer: fine)`; пальцы и стилус его не вызывают.
- Позиция пишется прямо в DOM в обработчике `pointermove`, без перерисовки Preact. Математика привязки к клетке — `src/ui/tui/cursor.ts`.

## Окна и первый запуск

- Все окна открываются F-клавишей, **той же клавишей закрываются**, другая клавиша переключает на своё окно; Esc и клик мимо закрывают. Окно всегда одно, F-клавиши перехватываются приложением (`preventDefault`), браузеру не достаются.
- **Настройки LLM** (F4, `/settings`) — окно с формой: язык, провайдер, ключ API, «запомнить ключ» (сразу под ключом), модель (окно выбора; список моделей провайдера подгружается после ввода ключа), согласие на обучение (если модель отдаёт данные), relay, кнопка «Проверить».
  Форма управляется клавиатурой (↑↓ — поле, ←→/Enter — изменить, в текстовом поле Enter — сохранить, Esc — отмена правки). Отдельной страницы `/settings` больше нет.
- **Первый запуск без настроек** (нет ключа, адреса relay/API, модели или нужного согласия): на экране **только окно настроек** — ни хроники, ни строки состояния, ни F-клавиш.
  Закрыть его Esc или кликом нельзя; уходит оно кнопкой **«Начать игру»**, которая проверяет заполнение и иначе пишет, чего не хватает. Первой строкой формы — язык (интерфейс переключается сразу).
  Решение «показывать ли окно» принимается один раз при загрузке страницы: если настройки уже есть, окно не навязывается; если ключ потом убрали, игра остаётся, а строка состояния показывает «LLM не настроен».
