# 0006. Firestore для состояния, RTDB для присутствия и стрима

- Статус: Accepted
- Дата: 2026-09-28

## Контекст
Firestore на Spark: 50K чтений и 20K записей в сутки, каждая запись оплачивается чтением у каждого слушателя.
Потоковый текст Мастера (десятки обновлений в секунду) и присутствие с `onDisconnect` в Firestore дороги или неудобны.

## Решение
- Firestore: кампании, коммиты, проекции, заявки. Всё долговременное.
- Realtime Database: `presence` (с `onDisconnect`), `stream` (живой текст Мастера, обновление ~250 мс), `typing`.
  На Spark RTDB ограничен объёмом и соединениями (1 ГБ, 10 ГБ/мес, 100 соединений), а не числом операций.
- Авторитетная аренда хоста остаётся в Firestore (там проверяют правила), RTDB только сигнализирует.

## Последствия
- + Бюджет Firestore около 10 записей и 50 чтений на ход для группы из 5.
- − Два набора правил безопасности и две подписки.
- − Лимит 100 одновременных соединений RTDB означает примерно 20 одновременных групп по 5 человек. Для проекта этого достаточно, форки получают свой лимит.
