# 0010. Шифрование секретов Мастера

- Статус: Accepted
- Дата: 2026-09-28

## Контекст
В кооп-кампании все данные лежат в Firestore и доступны участникам по правилам безопасности. Скрытый лор, тайные броски
и полные статблоки монстров видны любопытному игроку в DevTools. Серверного кода нет (ADR-0001), поэтому отдать секреты
«только серверу» некому. Владелец попросил самое быстрое решение, которое скрывает секреты.

## Решение
- У каждой облачной кампании есть ключ AES-GCM 256, созданный WebCrypto в браузере владельца. Ключ хранится в `campaigns/{cid}/secrets/key`.
- Правило Firestore: ключ читают только владелец и текущий держатель аренды хоста.
- Данные с `visibility: "dm"` хост шифрует перед записью (`src/net/secrets.ts`). В открытом виде остаются только поля, нужные для маршрутизации (`id`, `kind`, `t`, `visibility`).
- AAD = `cid` + id документа. IV случайный, 12 байт.

## Последствия
- + Не-хосты физически не получают ни ключ, ни открытый текст секретов.
- + Без зависимостей (WebCrypto встроен в браузеры), около 100 строк кода и тесты правил.
- − Хост видит всё (неустранимо без сервера).
- − Бывший хост мог сохранить ключ. Ротация ключа не делается, это принято.
- − Поиск по зашифрованному лору возможен только у хоста после расшифровки. Ретривер Мастера работает у хоста, так что это не мешает.

## Альтернативы
- Base64 или XOR-обфускация: быстрее на полдня, но расшифровывается в консоли за минуту. Отказ.
- Отдельная коллекция секретов с правилом «только хост» без шифрования: коммиты журнала общие, секреты в событиях всё равно утекли бы. Шифрование события проще.
- Секреты только в памяти хоста: теряются при смене хоста. Отказ.
