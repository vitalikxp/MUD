# 0014. Книги OpenD6 хранятся в git без LFS

- Статус: Accepted
- Дата: 2026-09-28

## Контекст
PDF книг OpenD6 (23 файла, 356 МБ, крупнейший 42,6 МБ) нужны агентам для сверки правил, в том числе по картинкам страниц.
Владелец хочет хранить их в GitHub. Ограничения GitHub (проверено 2026-09-28):
- обычный git: предупреждение для файлов больше 50 МиБ, блокировка больше 100 МиБ, рекомендуемый размер репозитория до 1 ГБ (строго рекомендуется до 5 ГБ);
- Git LFS (бесплатно): 10 ГиБ хранилища и 10 ГиБ трафика в месяц на аккаунт. При превышении и нулевом бюджете LFS блокируется до конца месяца.
  Трафик расходуют клоны, CI с `lfs: true`, архивы с LFS-объектами. Полный набор книг — 356 МБ, это примерно 28 клонов в месяц.

## Решение
- PDF коммитятся в **обычный git**, без LFS: каждый файл меньше 50 МиБ, общий объём меньше 1 ГБ.
- Правило: новый PDF больше 50 МиБ в репозиторий не добавляется (сжать или разбить; LFS — только отдельным ADR).
- CI деплоя не выкачивает `ref/` (sparse checkout), чтобы сборка оставалась быстрой.

## Последствия
- + Нет квот, которые могут закончиться и сломать клоны, когда за проектом никто не следит.
- + Любой клон или форк сразу получает книги, работают `search.py render` и сверка по картинкам.
- − Каждый полный клон весит примерно 360 МБ. Если книги не нужны: `git clone --filter=blob:none` (частичный клон, blobs по требованию) или sparse checkout без `ref/`.
- − Удалить книги из истории потом можно только переписыванием истории. Добавлять новые файлы стоит обдуманно.
- − Правовой нюанс: OGL разрешает распространять Open Game Content, а обложки, арт и логотипы в PDF — Product Identity (Purgatory Publishing).
  Книги 51000-серии издатель выпустил бесплатно, и их свободно распространяют на opend6.net, но формально права на арт OGL не даёт.
  Риск принимает владелец. Если придёт претензия, PDF удаляются из репозитория, а текстовый индекс (`ref/OpenD6/text/`) остаётся.

## Альтернативы
- Git LFS: квоты по трафику и блокировка при исчерпании противоречат цели «работает без присмотра». Отказ.
- Не хранить PDF (как было раньше): агенты без локальной копии не могут сверять таблицы по картинкам. Отказ по решению владельца.
- GitHub Releases как хранилище вложений: файлы вне дерева, скрипты усложняются. Отказ.
