# 0003. LLM рассказывает, движок решает

- Статус: Accepted
- Дата: 2026-09-28

## Контекст
Если в «ИИ-мастере» механика живёт в тексте, модель придумывает броски, забывает HP, путает инвентарь и подыгрывает игроку.
Главное обещание проекта: Мастер знает правила и честно их применяет.

## Решение
- Состояние игры и механику ведёт детерминированный движок (`src/engine`, `src/rules`).
- LLM меняет мир только вызовами инструментов (OpenAI tool calling), аргументы валидируются zod-схемами,
  исполняет их движок, а результат (например, итог броска) возвращается модели для повествования.
- Инструменты применяются к черновику состояния. Ход коммитится атомарно, только после `end_turn`.
- Карту модель видит через текстовое описание (`describe_map`) и меняет инструментами. ASCII-карты она не рисует.

## Последствия
- + Честность и воспроизводимость, состояние всегда согласовано с UI.
- + Правила тестируются unit-тестами без LLM.
- − Нужны модели с надёжным tool calling, слабые модели отпадают.
- − Больше запросов на ход (tool-loop), а значит больше задержка и токены.
- − Риск: модель пишет числа в тексте в обход инструментов. Смягчение — промпт, эвристика после хода, evals.

## Альтернативы
- Структурированный JSON-ответ целиком (повествование + действия) одним вызовом: модель не видит результат броска до повествования. Отказ как основной путь, возможен как фолбэк (FR-LLM-7).
- Только текст: не решает проблему.
