# 0018. Уровень рассуждений моделей и обязательные заголовки OpenCode Go

- Статус: Accepted
- Дата: 2026-09-28

## Контекст
Первая проверка ключа OpenCode Go на модели по умолчанию `muse-spark-1.3-contributor` (API `responses`, [ADR-0017](0017-default-model-muse-spark.md)) показала:

1. **Без заголовка `x-opencode-session` Go отвечает `400 MissingSessionID`.** В документации Go было только общее упоминание «session ID».
2. **Модель «думающая», и по умолчанию у неё `reasoning.effort: high`.** При `max_output_tokens: 300` все токены ушли на скрытые рассуждения
   (297 из 300), статус `incomplete`, текста нет. Токены рассуждений входят в `output_tokens` и оплачиваются как выход.
3. **Тест уровней рассуждений** (по одному прогону на уровень, 2026-09-28):

   | Сцена | Уровень | Время | Токены рассуждений | Результат |
   |---|---|---|---|---|
   | Ход по правилам: выстрел на 25 м + уклонение | low | 6,7 с | 470 | `attack(medium, 2 действия)` + `dodge(2 действия)` — верно |
   | | medium | 11,5 с | 1 004 | то же |
   | | high | 10,4 с | 1 022 | то же |
   | Творческое описание зала крипты | low | 10,4 с | 260 | сильный текст, точно по длине, обыграны зацепки лора |
   | | medium | 14,4 с | 588 | хороший текст, зацепки слабее |
   | | high | 15,0 с | 679 | самый детальный, длиннее заданного, придумал новое имя (факт для лора) |

   Разница в стоимости между `low` и `high` — меньше $0.0005 за ход. Разница в скорости — 4–5 секунд.
4. Модель выдумала ID персонажа (`Irma`) и вписала навык вместе с кодом кубов (`Взлом 4D+1`), когда схема инструмента допускала любую строку.
   Со схемой на `enum` (второй тест) аргументы были точными.

## Решение
- **Заголовки OpenCode Go**: клиент всегда отправляет `x-opencode-session` (значение — ID кампании, чтобы запросы одной кампании
  маршрутизировались вместе и лучше попадали в кэш промпта) и уникальный `User-Agent: swrd/<версия>`. Relay пропускает оба заголовка.
- **`reasoning.effort` — настройка роли в пресете** (для моделей, которые его поддерживают):
  - Мастер: **`medium`** — запас на сложные ходы (много игроков, длинная память, тактика NPC) при терпимой задержке;
  - Хранитель и помощники: **`low`**.
- **`max_output_tokens`** задаётся с запасом на рассуждения (для Мастера не меньше 4000). Статус `incomplete` с причиной
  `max_output_tokens` считается ошибкой хода с повтором и увеличенным лимитом, а не пустым ответом.
- **Схемы инструментов строятся из состояния**: ID сущностей, навыки, оружие и т. п. передаются как `enum` с реальными значениями текущей сцены.
  Свободные строки — только для `reason` и повествовательных полей.
- В M1 `eval:dm` сравнивает `low` и `medium` для Мастера на выборке сценариев. Если `low` не уступает, Мастер переходит на `low` ради скорости (новым ADR).

## Последствия
- + Без заголовка сессии интеграция с Go не работает вовсе. Теперь это требование, а не догадка.
- + Пустые ответы из-за исчерпанного лимита рассуждений не ломают ход.
- − Ход Мастера медленнее примерно на 4 секунды, чем на `low`. Цена ожидания компенсируется стримингом текста.
- − Модель стоимости из [ADR-0016](0016-default-models-pareto.md) занижала выход на ~1–3k токенов рассуждений за ход.
  Для Muse Spark это +$0.0003–0.0006 за ход, модель остаётся самой дешёвой.
