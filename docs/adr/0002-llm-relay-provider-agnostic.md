# 0002. Stateless-relay на Cloudflare Worker, провайдер-агностичный клиент

- Статус: Accepted. Набор форматов API расширен в [0015](0015-llm-three-api-formats.md)
- Дата: 2026-09-28

## Контекст
- Проверено 2026-09-28: `OPTIONS https://opencode.ai/zen/go/v1/chat/completions` возвращает 404 без заголовков CORS,
  поэтому браузер не может напрямую обращаться к API OpenCode Go.
- В документации OpenCode Go сказано: «designed for OpenCode and other coding agents… Traffic is monitored for abuse».
  Игровой Мастер не coding agent, ключ могут заблокировать.
- Многие провайдеры (OpenRouter, Gemini OpenAI-compatible, локальный Ollama) разрешают CORS.

## Решение
- Клиент `src/llm/` работает с любым OpenAI-совместимым Chat Completions API (стриминг SSE, `tools`).
  Провайдеры описаны пресетами: base URL, нужные заголовки, режим (relay или direct), подсказка по моделям. OpenCode Go — один из пресетов.
- Relay — Cloudflare Worker (Free: 100K запросов в сутки, ожидание сети не входит в CPU-лимит, стриминг разрешён):
  проксирует запрос к upstream из allowlist, пропускает `Authorization` игрока, ничего не хранит и не логирует.
- URL relay настраивается у клиента, а код лежит в `relay/`, так что любой может поднять свою копию.

## Последствия
- + Проект не зависит от одного провайдера и его условий.
- + Relay простой (десятки строк), его почти нечему ломаться.
- − Relay — формально точка, через которую проходит ключ. Нужны открытый код, отсутствие логов и возможность прямого режима.
- − Лимит 100K запросов в сутки общий на всех пользователей встроенного relay.

## Альтернативы
- Только CORS-дружественные провайдеры: отрезает OpenCode Go, которым пользуется автор. Оставлено как режим `direct`.
- Публичные CORS-прокси: ключ уходит третьим лицам. Отказ.
