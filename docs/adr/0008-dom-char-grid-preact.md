# 0008. TUI на DOM-сетке символов, Preact + Signals

- Статус: Accepted. Шрифт: единственный PxPlus, без переключения — [0020](0020-single-font.md)
- Дата: 2026-09-28 (до начала кода React + Zustand заменён на Preact + Signals по решению владельца)

## Контекст
Нужен интерфейс «как Norton Commander»: строгая сетка знакомест, рамки из псевдографики, кириллица, палитры,
при этом доступность (скринридеры, выделение текста, IME на мобильных) и адаптивность.
Проекту важна долговечность: чем меньше и проще зависимости, тем лучше.

## Решение
- Рендеринг в DOM: строки из цветовых отрезков (`<span>` на отрезок, не на ячейку), `white-space: pre`, моноширинный self-hosted шрифт,
  раскладка в ячейках, цвета через CSS-переменные токенов палитры.
- **Preact** (`preact`, `@preact/preset-vite`) + **`@preact/signals`** для состояния приложения.
  - Стор в `src/app/` — набор сигналов и `computed` поверх проекций движка. Отдельной библиотеки стора нет.
  - Горячие панели (карта, хроника) подписываются на сигналы своих строк, поэтому движение фишки перерисовывает 1–2 строки, а не панель.
  - `preact/compat` **не подключаем** по умолчанию. Если какой-то библиотеке понадобится React API, это отдельное решение с обоснованием.
- Тесты компонентов: `@testing-library/preact` + Vitest (jsdom).
- Пакетный менеджер: pnpm.

## Последствия
- + Рантайм около 4 КБ gzip (React + ReactDOM около 45 КБ), что помогает уложиться в NFR-PERF-1.
- + Сигналы дают точечные обновления без ручной мемоизации, а это подходит сетке символов.
- + Меньше зависимостей: отпадает Zustand.
- − Экосистема компонентов меньше, чем у React. Для TUI это неважно, все примитивы свои.
- − Агентам нужно помнить: импорты из `preact` и `preact/hooks`, а не `react`; `class` допустим наравне с `className`.
- − Нужна аккуратность с метриками шрифта (зазоры в рамках, дробная ширина ячейки). Обязательна страница `/dev/glyphs`.
- − На очень больших картах возможны проблемы производительности. Запасной путь — `<canvas>` только для `MapView`.

## Альтернативы
- React 19 + Zustand: знаком по соседним проектам, но тяжелее и требует ручной мемоизации горячих панелей.
- Solid: тоже сигналы, отличная производительность, но менее знаком и дальше от React-синтаксиса, привычного агентам.
- Полностью canvas (как xterm.js или rot.js): идеальная сетка, но плохая доступность, свой ввод и перенос. Отказ для UI, возможен для карты.
- xterm.js как «настоящий терминал»: заточен под потоки ANSI, а не под панели с состоянием. Отказ.
