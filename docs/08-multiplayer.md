# 08. Кооператив

([ADR-0005](adr/0005-host-authoritative-coop.md))

## Модель

- **Хост** — участник, в чьём браузере работает оркестратор Мастера. LLM вызывается его ключом.
  Только хост пишет коммиты и проекции.
- **Игроки** пишут заявки, черновики персонажей и OOC-чат. Всё остальное они только читают через подписки Firestore и стрим RTDB.
- Любой участник с настроенным LLM **может стать хостом**, если текущий хост недоступен: состояние кампании полностью лежит в Firestore.

## Жизненный цикл

```
lobby ──(владелец: «Начать»)──► session_zero ──(канон принят, все персонажи приняты)──► explore ⇄ combat
```

1. **Создание.** Владелец создаёт облачную кампанию и получает ссылку `/#/join/{cid}?code=XXXX-XXXX`.
2. **Вход.** Игрок открывает ссылку и проходит анонимный вход (Google можно привязать позже). Правило Firestore добавляет его в `members`, если хэш кода совпал.
3. **Лобби.** Видно участников, онлайн-статус (RTDB presence), хоста и черновики персонажей.
   Если модель Мастера обучается на данных (`*-contributor`), участник видит предупреждение и подтверждает согласие (`modelConsent`, [ADR-0017](adr/0017-default-model-muse-spark.md)). Без согласия он не может отправлять заявки, пока хост не сменит пресет на «Приватный».
4. **Сессия ноль.** Хост запускает развёртку шаблона. Игроки создают персонажей в `drafts/{uid}`, хост принимает их: модуль валидирует, появляется событие `entity.created`.
5. **Игра.** Идут раунды заявок.

## Раунд заявок

```
round.open ──► игроки пишут intents/{roundId_uid} { text | pass, ready } ──► условие закрытия ──► round.closed ──► ход Мастера ──► round.open
```

- Заявку можно редактировать, пока раунд открыт. «Готов» фиксирует её (с возможностью снять).
- **Условия закрытия** (любое):
  - все **онлайн**-участники с персонажем отметили «готов»;
  - истёк `deadline`, если хост задал таймер (по умолчанию выключен, режим play-by-post);
  - хост нажал «Закрыть раунд».
- Офлайн-игрок считается «пас». Мастер может отметить его персонажа как «следует за группой».
- Мастер отвечает **одним** повествованием на раунд и обращается к каждому, чья заявка была.
- `/ooc` в строке ввода отправляет сообщение в OOC-чат, а не в заявку.

### В бою

Фаза `combat`: раунд заявок заменяется **очерёдностью** по инициативе.
- Ход персонажа игрока: заявку пишет только этот игрок, раунд закрывается его «готов» (или таймером боя, если он задан).
- Ход NPC: хост сразу запускает Мастера (`npc_action`).
- Остальные видят «Ходит: Борк». Их ввод идёт в OOC.

## Аренда хоста

```
campaigns/{cid}.hostLease = { uid, expiresAt }
```
- Хост продлевает аренду **транзакцией** каждые 30 с (`expiresAt = now + 90 s`).
- Присутствие видно через RTDB `presence` (быстро, с `onDisconnect`), но **авторитетна аренда в Firestore**. Правила безопасности проверяют именно её.
- **Захват**: если `expiresAt < now` и у участника настроен LLM, он видит кнопку «Взять роль Мастера». Транзакция срабатывает только при истёкшей аренде.
  Правило Firestore разрешает не-владельцу менять в документе кампании только `hostLease`, и только если аренда истекла.
- **Добровольная передача**: хост нажимает «Передать роль Мастера» → выбирает участника → тот подтверждает.
- Новый хост загружает проекции и `headSeq` и продолжает с открытого раунда. Если хост умер посреди хода, ход не был закоммичен, и раунд просто закрывается заново.
- Ключ LLM, модель и расход токенов у каждого хоста свои. В UI видно, кто сейчас платит за ход.

## Стрим повествования

- Хост получает дельты от LLM и накапливает текст. Раз в 250 мс, а также на границах абзацев, пишет `stream/{cid}` = `{ turnId, text, done }`.
- Клиенты показывают стрим как «Мастер говорит…» поверх хроники. После коммита хода отображается версия из коммита, стрим очищается.
- Вызовы инструментов в процессе показываются в стриме короткими строками (`♦ Бросок…`). Итоговые события приходят с коммитом.

## Консистентность и конфликты

| Ситуация | Поведение |
|---|---|
| Два клиента считают себя хостом | Коммит пишется в транзакции с проверкой `headSeq` и аренды, проигравший получает ошибку и переходит в режим игрока |
| Игрок отправил заявку после закрытия раунда | Правило отклоняет запись, UI переносит текст в следующий раунд |
| Хост потерял сеть во время хода | Ход не закоммичен, аренда истекает, другой участник может перехватить роль |
| Игрок бытовым действием трогает то же, что Мастер в текущем ходу | `ui.action` ждёт окончания хода и применяется к новому состоянию или отклоняется с объяснением |

## Приватность в группе

- Секреты Мастера (скрытый лор, тайные броски, полные статблоки) лежат в Firestore **зашифрованными**. Ключ читает только текущий хост
  ([ADR-0010](adr/0010-dm-secrets-encryption.md), [06](06-data-model.md#шифрование-секретов-мастера)). Любопытный игрок в DevTools увидит шифротекст.
- Хост видит всё: секреты расшифровываются в его браузере, иначе Мастер не смог бы вести игру. Это принятое ограничение.
- Остальные данные кампании (повествование, открытый лор, броски на виду) доступны всем участникам.
