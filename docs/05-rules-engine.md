# 05. Движок правил

## Ядро и модули

Ядро (`src/engine/`) ничего не знает о конкретной системе. Оно умеет:
- бросать кубы на сидированном RNG: классические формулы (`NdX±M`, `src/engine/classic.ts`). **Пулы d6 с Wild Die** (`4D+2`, дополнительные Wild Die за CP, удвоение за FP; см. ниже) — часть OpenD6 и живут в `src/rules/opend6/dice.ts` (AGENTS.md §4.7, §4.12); в журнале движок хранит подробности броска как непрозрачный JSON;
- хранить сущности (персонажи, NPC, монстры, предметы) с произвольным блоком `stats`, который описывает модуль;
- вести очередь боя, карту, фишки, туман;
- применять события.

Всё, что специфично для системы, реализует **модуль правил** ([ADR-0007](adr/0007-modular-rules.md)).
Первый модуль — **OpenD6** ([ADR-0011](adr/0011-opend6-first-module.md)).

## Интерфейс `RulesModule` (черновик)

```ts
export interface RulesModule<Stats = unknown, Item = unknown> {
  id: string;                    // "opend6"
  version: string;               // semver; сохраняется в кампании
  name: LocalizedString;
  license: { id: string; notice: string };        // напр. OGL-1.0a + текст Section 15 (показывается в «О программе»)

  // Варианты (жанровые наборы характеристик); шаблон сеттинга выбирает один
  variants: RulesVariant[];                        // напр. "fantasy", "adventure"

  // Персонажи
  characterSchema(variant): ZodType<Stats>;        // что лежит в entity.stats
  creation: {                                      // реализовано (src/rules/api.ts, FR-CHR-1)
    templates(variant): CreationTemplate[];        //   готовые шаблоны: описание, характеристики, особенности, навыки для раскладки
    budget(variant): { total; maxPerSkill; format(points) }; // очки навыков (OpenD6: 7D = 21 очко, не больше +3D в навык)
    build(input): Result<Entity>;                  //   шаблон + имя + очки навыков → персонаж, проверенный правилами
  };
  derive(stats: Stats): DerivedStats;              // защита, макс. Тело, штрафы ран — то, что считается
  sheetLayout(variant): SheetLayout;               // как рисовать лист в TUI
  advancement: { options(stats): Improvement[]; apply(stats, imp): Result<Stats> }; // рост персонажа

  // Предметы
  itemSchema: ZodType<Item>;
  inventoryRules: { capacity(stats: Stats): Capacity; canEquip(stats, item, slot): Result };

  // Механика (всё чистое: state + args + rng → события)
  roll(ctx: RulesCtx, args: RollArgs): Result<Outcome>; // реализовано: свободный бросок (2d6+1 или 4D+1), без персонажа
  check(ctx: RulesCtx, args: CheckArgs): Outcome;
  contest(ctx: RulesCtx, args: ContestArgs): Outcome;
  attack(ctx: RulesCtx, args: AttackArgs): Outcome;
  applyDamage(ctx: RulesCtx, args: DamageArgs): Outcome;
  initiative(ctx: RulesCtx, participants: EntityId[]): Outcome;
  movement(ctx: RulesCtx, entityId: EntityId): { cellsPerTurn: number };
  onTurnStart?/onTurnEnd?/onRest?(ctx, ...): Outcome;

  // Ресурсы игрока, которые тратятся на бросок (у OpenD6 — Очки персонажа и Очки судьбы)
  spendables?: SpendableDef[];

  // Расширения Мастера
  extraTools?: ToolDefinition[];                   // напр. cast_spell
  conditions: ConditionDef[];

  // Контент
  bestiary: MonsterDef[];                          // статблоки для spawn и карточек
  items: ItemDef[];

  // Для LLM
  promptPrimer(variant, lang: Lang): string;       // ≤ ~1.5k токенов: как играть по этим правилам
  lookup(topic: string, lang: Lang): string | null;// для rules_lookup

  // Совместимость сохранений
  migrate?(fromVersion: string, stats: unknown): Stats;
}

type Outcome = { events: GameEvent[]; result: Record<string, unknown> }; // result возвращается LLM
```

Правила:
- Функции модуля **чистые**: `Math.random` и `Date` не используются, RNG приходит в `ctx`.
- Модуль проверяет **всё**: доступно ли действие, дистанцию, ресурсы. Отказ возвращается как `Result.error` с объяснением для LLM.
- Весь контент модуля двуязычный (`LocalizedString = { ru: string; en: string }`).
- Модуль и вариант фиксируются в кампании по `id`, `version` и `variant`. После старта кампании они не меняются, возможна только миграция версии.
- Модуль несёт свою лицензию. Код и данные модуля лежат в его каталоге вместе с файлом лицензии.
- Расширения интерфейса, добавленные к черновику в M1.5 (реализованы в `src/rules/api.ts`): `roll` (свободный бросок), `npc.create` (простой NPC по уровню: все характеристики одного кода, Очки тела = среднее Телосложения + 20),
  `describe(entity)` (компактное описание для промпта с id навыков), `items.ids/make/search` (каталог снаряжения для Мастера), `lookupTopics`; `DamageArgs.attackerId` — оружие с «+» в коде прибавляется к Силе удара атакующего.

### Варианты

Жанровые книги OpenD6 используют разные наборы характеристик. Модуль поддерживает варианты, а шаблон сеттинга выбирает один:

| Вариант | Книга | Характеристики | Экстранормальное | Шаблон |
|---|---|---|---|---|
| `fantasy` | D6 Fantasy (`fantasy` p.11) | Ловкость (Agility), Координация (Coordination), Телосложение (Physique), Интеллект (Intellect), Смекалка (Acumen), Обаяние (Charisma) | Экстранормальная: Магия (Magic), Чудеса (Miracles) | «Пограничье» |
| `adventure` | D6 Adventure (`adventure` p.11) | Рефлексы (Reflexes), Координация (Coordination), Телосложение (Physique), Знания (Knowledge), Восприятие (Perception), Присутствие (Presence) | Экстранормальная: магия и псионика есть в книге, в MVP не используется | постапокалипсис «Пепел» |

Механика (Mechanical) и Техника (Technical) — характеристики *D6 Space*, а не *D6 Adventure*. В постапокалипсисе технику покрывают навыки.

Русские названия характеристик и навыков — рабочие, утверждаются вместе с глоссарием модуля в M1.

### Коды кубов и Wild Die

- Характеристики и навыки записываются **кодом кубов**: `3D+1` — бросить три d6 и прибавить 1. **3 «пипа» = 1D** (`2D+2` + 1 пип = `3D`).
- Навык указывается как надбавка к характеристике: навык «Скрытность +1D» при Ловкости `3D` даёт бросок `4D`.
- Один из кубов броска — **Wild Die**:
  - выпало **6** — оно прибавляется, и Wild Die бросается ещё раз, пока выпадают шестёрки (взрыв);
  - выпало **1** на первом броске (Critical Failure) — Мастер выбирает: единица «гасит» наибольший куб (оба не считаются)
    или сумма считается как обычно, но возникает **осложнение**, связанное с действием. На повторных бросках Wild Die единица осложнений не даёт (`adventure` p.47).
- Движок бросает кубы и записывает в событие все кубы, цепочку Wild Die и флаг осложнения. Выбор при единице передаётся Мастеру в `result`,
  и он решает его вызовом того же инструмента (параметр `onWildOne`) или по настройке кампании (по умолчанию — осложнение).

### Проверки

Сумма броска сравнивается со **сложностью** и должна её достичь или превысить. Мастер выбирает сложность до броска:

| Сложность | Диапазон | Типичное число |
|---|---|---|
| Автоматически | 0 | без броска |
| Очень легко | 1–5 | 5 |
| Легко | 6–10 | 10 |
| Средне | 11–15 | 15 |
| Трудно | 16–20 | 20 |
| Очень трудно | 21–25 | 25 |
| Героически | 26–30 | 30 |
| Легендарно | 31+ | 35+ |

Шкала: `adventure` p.53, p.141.

- **Только Wild Die**: если исход почти гарантирован, но осложнение важно для сцены, бросается один Wild Die. 6 — неожиданная удача, 1 — мелкое осложнение (`adventure` p.53).
- **Встречная проверка**: оба бросают, больший результат побеждает, **ничья — в пользу инициатора**. Обе стороны тратят действие (`adventure` p.53).
- **Производная сложность**: против персонажа, который не может активно сопротивляться, сложность = 2 × число кубов его характеристики или навыка + пипы (пример: Присутствие 3D даёт 6) (`adventure` p.53).
- **Без навыка**: бросается характеристика, к сложности обычно +5 (от +1 для простых задач). Не применяется к броскам, где характеристика указана явно (сопротивление, уклонение, рукопашная в бою, поиск улик, сила воли) (`adventure` p.49).
- **Модификаторы обстоятельств**: ±1–5 (слабое), ±6–10 (значительное), ±11–15 (решающее), ±16+ (подавляющее) к сложности (`adventure` p.53). Модель передаёт их с причиной, модуль ограничивает диапазон.
- **Разница** между результатом и сложностью возвращается модели (`margin`) и используется как степень успеха в повествовании.

### Очки персонажа и Очки судьбы

`adventure` p.47–48, `fantasy` p.48–49.

- **Очки персонажа (CP)**: каждое потраченное очко добавляет к броску **ещё один Wild Die** (с взрывом на 6; единица на нём считается просто как 1, без осложнения).
  Максимум очков на бросок зависит от уровня приключения: 2 (лёгкое), 5 (кинематографичное), без лимита (эпическое). В проекте это настройка кампании `cpMaxPerRoll`, по умолчанию **5**.
  По книге CP можно тратить до или после броска, но до объявления результата. CP тратятся на любые броски, включая урон и инициативу, а также на развитие персонажа.
- **Очко судьбы (FP)**: удваивает число кубов броска (характеристика или навык с пипами; кубы оружия и бонусы снаряжения не удваиваются; Wild Die остаётся один).
  Только **до** броска, обычно не больше одного FP на бросок за раунд. Раз за сессию можно потратить FP «кульминационно»: удваиваются все броски персонажа в этом раунде. На инициативу FP тратить нельзя.
  FP, потраченное в согласии с моральным кодексом персонажа, может вернуться в конце игры. Потраченное против кодекса может стоить ещё одно FP.
- **CP и FP в одном броске** не сочетаются (кроме особо кинематографичных ситуаций по решению Мастера).
- Старт: 5 CP и 1 FP (`adventure` p.11).
- **Как тратит игрок** (Q7: кубы бросаются автоматически): в заявке переключатели «+CP ×N» и «Очко судьбы». Движок применяет трату
  к первому подходящему броску этого персонажа в ходе. Трата CP после броска — после MVP (см. «Отступления»).
- Награда в конце сцены или сессии выдаётся инструментом `award_points(targetIds, cp, fp?, reason)`.

### Создание персонажа

- Кубы на характеристики: **18D** на семь характеристик (шесть + Экстранормальная), минимум 1D, максимум 5D.
  У Экстранормальной нет ни минимума, ни максимума, у большинства персонажей она 0D (`adventure` p.10, `fantasy` p.10).
  Кубы можно делить на пипы: 1D = 3 пипа, например 4D = `2D+1` + `1D+2` (`adventure` p.12).
- Кубы на навыки: **7D**, не больше +3D в один навык. Все навыки начинаются с кода кубов своей характеристики (`adventure` p.10, p.12).
- Специализации: 1 кубик навыка = 3 кубика специализации. Специализация работает только в своей узкой области (`adventure` p.12).
- Альтернатива — готовые шаблоны: характеристики уже распределены, игрок раскладывает 7D навыков (`adventure` p.10).
- Преимущества, недостатки и особые способности (`adventure` p.16–43, `fantasy` p.16–42):
  в MVP ограниченный список из 10–15 штук на вариант, остальное позже.
- **Готовые шаблоны персонажей** (`src/rules/opend6/templates.ts`, по 6 на вариант из книжных шаблонов без магии и псионики):
  `fantasy` — Бард, Гладиатор, Целитель, Истребитель чудовищ, Следопыт, Вор (p.129–136);
  `adventure` — Телохранитель, Корреспондент, Врач, Полевой учёный, Завязавший вор, Мастер оружия (p.129–138).
  В книге шаблон задаёт **только характеристики** (ровно 18D; у Телохранителя в книге 18D+1, оставлено как есть), Очки тела, Funds/серебро,
  особенности и снаряжение, а у навыков указан лишь перечень: 7D игрок (или Мастер в диалоге) раскладывает сам, результат проверяет `validateCreation`.
  Опционально с ИИ-помощью «подогнать шаблон под концепт» ([FR-CHR-2](02-requirements.md)).
- Преимущества, недостатки и способности хранятся в `data.traits` (вид, название RU/EN, ранг, описание): механику по описанию применяет Мастер.

### Бой

`adventure` p.49–50, p.59–61; `fantasy` p.50–52, p.61–63.

- **Раунд** — 5 секунд. Одно действие в раунде без штрафа.
- **Инициатива**: бросок Восприятия (`adventure`) или Смекалки (`fantasy`), бросает движок. На инициативу можно тратить CP, но не FP.
  Ничья и режим «без бросков»: сравниваются коды кубов по порядку — способность ходить первым, Восприятие, поиск, Рефлексы, уклонение.
  Бросок один раз на сцену (быстрый вариант книги) — используем его. Вариант «каждый раунд» — настройка кампании.
- **Несколько действий**: −1D ко **всем** броскам навыков и характеристик в раунде за каждое действие сверх первого. На урон, сопротивление урону и инициативу штраф не действует.
  Ожидание — тоже действие. Число действий объявляется в начале своего хода.
- **Сложность атаки**: базово **10** (пассивная защита цели) плюс модификаторы. Итог никогда не меньше **3**.
  - **Дистанция**: вплотную (0–3 м) −5, короткая 0, средняя +5, дальняя +10. Границы — из таблицы дистанций оружия. Рукопашная — только вплотную.
  - **Укрытие и видимость**: лёгкий дым или сумерки +1D (+3), густой дым или лунная ночь +2D (+6), очень густой дым или полная темнота +4D (+12);
    объект закрывает 25% цели +1D (+3), 50% +2D (+6), 75% +4D (+12), 100% — стрелять нужно по укрытию.
  - **Прицеливание**: +1D за каждый раунд без других действий, максимум +3D.
- **Активная защита** (уклонение, блок, парирование) — это действие на своём ходу. Её результат заменяет сложность для всех атак до своего следующего хода.
  **Полная защита** (все действия раунда отдаются защите): результат + 10. Неудачная активная защита может оказаться ниже 10 — это тоже результат.
- **Урон**: код урона оружия. Если перед кодом стоит «+» (`+1D`), он складывается с **Strength Damage** атакующего.
  Strength Damage = кубы Телосложения (или lifting) без пипов, делённые на 2 с округлением вверх: Телосложение 3D → 2D (`adventure` p.15, p.61).
  Опционально: бонус урона = (результат атаки − сложность) / 5 с округлением вверх. Используем его — он делает удачные атаки ощутимыми.
- **Движение**: Move = 10 м за раунд (`adventure` p.10). На карте 1 клетка = 1,5 м, значит примерно 6 клеток. Бег сверх Move — проверка навыка бега (`adventure` p.55).
- Мораль и бегство NPC решает Мастер (`npc_action`), при необходимости с проверкой.

### Здоровье: Очки тела

В OpenD6 есть два варианта учёта урона: **Очки тела** (Body Points) и **Уровни ран** (Wounds) (`adventure` p.62). В MVP используем **Очки тела**:
они естественно показываются полосой в TUI и проще для LLM.

- Максимум Очков тела: бросок Телосложения + 20 при создании. Единица на Wild Die здесь считается просто как 1 (`adventure` p.15).
- **Сопротивление урону** в системе Очков тела: бросок кодов кубов доспеха и особых способностей (например, Increased Attribute: Physique) минус штрафы от болезней и ядов.
  Телосложение в сопротивление не входит. Урон − сопротивление вычитается из Очков тела. Если сопротивление ≥ урона, ранения нет (`adventure` p.62–63).
- По мере потери Очков тела наступают **уровни ранения** (`fantasy` p.65, сверено по картинке страницы):

  | Уровень | Осталось Очков тела | Эффект |
  |---|---|---|
  | Ушиб (Bruised) | 81–99% | нет |
  | Оглушён (Stunned) | 60–80% | −1D на остаток раунда и следующий раунд или только защита/отступление |
  | Ранен (Wounded) | 40–59% | −1D на все действия до лечения |
  | Тяжело ранен (Severely Wounded) | 20–39% | −2D на все действия до лечения |
  | Недееспособен (Incapacitated) | 10–19% | проверка stamina/mettle 15, иначе без сознания; при успехе −3D |
  | При смерти (Mortally Wounded) | 1–9% | без сознания, каждый раунд бросок Телосложения; если меньше числа минут на этом уровне — смерть |
  | Мёртв (Dead) | 0 | — |

  Штрафы уровней не суммируются и не применяются к броскам урона и сопротивления.
  Уровень ранения — производная величина (`derive`), он показывается рядом с полосой: `Тело ██████░░ 22/31 · Ранен (−1D)`.
- **Лечение** (`adventure` p.65–66):
  - естественное: раз в сутки бросок Телосложения с модификатором за отдых (+1D — весь день отдыха, 0 — лёгкая активность, −1D — бой и бег).
    Очки тела восстанавливаются в начале следующего дня по таблице «Body Points Healing» (сверено по картинке страницы):

    | Результат (Телосложение или медицина) | 0 | 1–5 | 6–10 | 11–15 | 16–20 | 21–25 | 26–30 | 30+ |
    |---|---|---|---|---|---|---|---|---|
    | Восстановлено Очков тела | 0 | 2 | 1D | 2D | 3D | 4D | 5D | 6D |

  - навыком медицины: бросок по той же таблице, аптечка даёт свой бонус. Лечить одного пациента можно раз в сутки, помощники добавляют свой навык к первому лекарю;
  - больше максимума вылечить нельзя.
- Вариант «Уровни ран» — после MVP, как настройка кампании.

### Магия (вариант `fantasy`)

Магия D6 Fantasy построена на формулах заклинаний (навыки Изменение, Перемещение, Сотворение, Прорицание — Alteration, Apportation, Conjuration, Divination; `adventure` p.84, `fantasy` p.84; сложность считается по параметрам эффекта).
Для LLM и UI это слишком тяжело, поэтому в MVP:
- **готовый список** из 8–12 заклинаний, взятых из «Precalculated Spells» книг (`fantasy` p.98–103, `magic` p.32–33) со сложностью и эффектом, уже рассчитанными авторами (данные в `spells.yaml`);
- инструмент `cast_spell(casterId, spellId, targets)` — модуль делает проверку навыка против сложности заклинания и применяет эффект;
- конструктор заклинаний — после MVP.

### Инвентарь

- В книге нет лимита переносимого веса для инвентаря: есть только проверка lifting при подъёме и переноске конкретного тяжёлого предмета (`adventure` p.78).
  Для UI нужен понятный предел, поэтому вводим слоты: **слоты = кубы Телосложения × 3 + 5** (отступление №1).
- **Доспех** даёт Armor Value в кодах кубов. Сочетания слоёв ограничены правилами книги (`adventure` p.115–116, `fantasy` p.116–117).
- Экипировка: доспех, щит, основная рука, вторая рука, 2 кольца/аксессуара, пояс (3 слота быстрого доступа).
- Снаряжение и оружие — полные каталоги глав Equipment в `src/rules/opend6/catalog/` (`adventure` p.114–121, `fantasy` p.115–120): снаряжение, одежда и еда (fantasy),
  доспехи и щиты, ближнее оружие, стрелковое и метательное, огнестрельное и энергетическое (adventure), взрывчатка, транспорт. У записи есть цена (сложность покупки VE…L и монеты в fantasy),
  свойства (`data` → `Item.data`) и, где у предмета есть эффект, краткая заметка. Запись превращается в предмет через `catalogItem`; `Item.ref = opend6:<вариант>:<id>`.
- Свойства предметов (`Item.data`): `armor` — Armor Value кодом кубов (`"2"` = +2 без броска, `"1D"` — бросается; складывается по надетым предметам), `zone` — броня защищает только эту часть тела (`applyDamage(zone)`),
  `weapon` — `melee` | `missile` | `thrown` | `firearm` | `energy` | `explosive`, `damage` (с «+» — плюс Сила удара), `range` (м или «PHYS±N»), `ammo`, `unwieldy` (длиннее 60 см), `bonus` — бонус к навыку.
  `shield: true` — щит: его защита учитывается, только если Мастер передал `shielded` (щит был между атакующим и целью, `fantasy` p.116).
  Правила сочетания слоёв брони и максимум сопротивления 6D книга оставляет Мастеру и опциональны — движок их не проверяет.
- Деньги: Funds хранятся как в книге (`data.funds`, код кубов; покупка — проверка Funds против сложности цены, `adventure` p.113), в фэнтези ещё серебро (`data.silver`); 8 C = 1 S, 8 S = 1 G (`fantasy` p.114).

  - { id: paralyzing_touch, text: { ru: "…", en: "…" } }

### Отступления от книги

Каждое отступление — осознанное упрощение ради LLM или UI с кратким обоснованием.

| # | Отступление | Почему |
|---|---|---|
| 1 | Слоты инвентаря = кубы Телосложения × 3 + 5 (в книге лимита нет, только проверки lifting) | UI нужен понятный предел, LLM проще следить за переполнением |
| 2 | CP тратятся только до броска (в книге — до или после, но до объявления результата) | броски автоматические (Q7). Трата после броска — после MVP |
| 3 | Покупки решает Мастер по цене предмета (сложность и монеты), движок Funds-проверку пока не автоматизирует | пока нет торговли; Funds и серебро в листе хранятся как в книге |
| 4 | Только готовые заклинания, без конструктора | конструктор слишком тяжёл для LLM и UI в MVP |
| 5 | «Оглушён» (60–80%) даёт −1D, пока Очки тела на этом уровне (в книге штраф только на остаток раунда и следующий) | нет учёта раундов вне боя; проще для движка и листа |
| 6 | Смерть при 0 Очков тела без окна реанимации; на уровне «при смерти» (1–9%) персонаж без сознания, но бросков «минут до смерти» движок не делает | достаточно для соло-игры; «при смерти» оставляет время на лечение по решению Мастера |
| 7 | На уровне «недееспособен» (10–19%) движок применяет −3D, но проверку стойкости 15 на сознание не бросает сам: её вызывает Мастер инструментом `check` | не привязывать движок к боевому раунду |
