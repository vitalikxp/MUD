# Книги OpenD6: инструкция для агентов

Здесь лежат книги OpenD6 (OGL 1.0a), по которым пишется модуль правил `opend6`, и индекс для быстрого поиска по ним.
Книги на **английском**, искать нужно английскими терминами (соответствия RU↔EN — в [docs/glossary.md](../../docs/glossary.md)).

## Что где

| Путь | Что | В git |
|---|---|---|
| `*.pdf` | Оригиналы книг (356 МБ, каждый файл < 50 МиБ) | да, обычный git без LFS ([ADR-0014](../../docs/adr/0014-reference-books-in-git.md)) |
| `text/<slug>.md` | Полный текст книги постранично: `## p.N · Глава` перед каждой страницей | да |
| [INDEX.md](INDEX.md) | Каталог: slug, книга, приоритет для SWRD, наличие текста, оглавления | да, генерируется |
| [TOPICS.md](TOPICS.md) | Карта тем проекта → книга и страницы | да, ведётся руками |
| `scripts/ref/extract.py` | Пересборка `text/` и `INDEX.md` из PDF | да |
| `scripts/ref/search.py` | Поиск, чтение страниц, оглавления, рендер страниц в PNG | да |

`p.N` — **номер страницы PDF** (как в просмотрщике). Печатный номер на странице книги обычно на 1 меньше.

## Когда обращаться к книгам

**Обязательно**, если задача касается:
- кода или данных в `src/rules/opend6/` (механика, навыки, преимущества, снаряжение, заклинания, бестиарий, шаблоны персонажей);
- чисел и правил в [docs/05-rules-engine.md](../../docs/05-rules-engine.md), особенно помеченных ⚠ — их нужно сверить до написания кода;
- `promptPrimer` и `rules_lookup` (что Мастер знает о правилах);
- evals по правилам (ожидаемые сложности, урон, исходы);
- статблоков монстров и NPC для шаблонов сеттингов.

**Полезно**: промпты Мастера (советы по ведению игры), идеи для шаблонов сеттингов и карт (книги Locations).

**Не нужно**: движок событий, хранилище, UI, LLM-клиент, relay, инфраструктура. Там правил OpenD6 нет.

## Как искать эффективно

Порядок, который экономит контекст:

1. **[TOPICS.md](TOPICS.md)**: найти тему и получить книгу и страницы. Чаще всего этого достаточно.
2. **Прочитать только нужные страницы**:
   ```bash
   python3 scripts/ref/search.py page adventure 59-61
   ```
3. **Если темы нет в карте — поиск** (regex, регистр не важен, пробел в запросе совпадает и со слипшимися словами):
   ```bash
   python3 scripts/ref/search.py "called shot" -b adventure,fantasy
   python3 scripts/ref/search.py "strength damage" -C 3 --limit 3
   python3 scripts/ref/search.py "initiative" --all          # включая книги приоритета 3
   ```
   Результаты сгруппированы по страницам и отсортированы по числу совпадений. Служебные главы (Contents, Index) исключены (`--toc` вернёт их).
4. **Оглавление книги**: `python3 scripts/ref/search.py toc magic` или раздел в [INDEX.md](INDEX.md).
5. **Визуальная сверка** таблиц и сомнительных чисел (нужен PDF): `python3 scripts/ref/search.py render fantasy 65 --out <scratchpad>`,
   затем открыть PNG инструментом чтения изображений.

Запрещено:
- **Читать `text/*.md` целиком**: один файл занимает до 200k токенов. Только `page`, поиск или чтение с offset/limit.
- **Читать PDF напрямую**: это тяжело и медленно. Для картинки страницы есть `render`.
- **Брать числа по памяти.** Если правило не найдено, так и напиши в отчёте и не выдумывай.

## Надёжность текста

| Книга | Качество | Что делать |
|---|---|---|
| `adventure`, `magic`, `system-book`, `gm-screen`, creatures, locations, `space` | чистый текстовый слой | можно доверять |
| `fantasy`, частично `fantasy-creatures` | текст получен распознаванием с ошибками: `ID`→1D, `SD`→5D, `OD`→0D, `lf`→If, `Pate`→Fate, слипшиеся слова | числа сверять с тем же правилом в `adventure` (механика почти одинаковая) или через `render` |
| `space-ships` | скан без текста | поиск не работает. Нужен OCR (`tesseract` не установлен), приоритет 3 |
| `sheet-*` | бланки-картинки | смотреть через `render` |

Если книги расходятся: правило книги варианта (`fantasy` для `fantasy`, `adventure` для `adventure`) → `gm-screen` → `system-book`.

## Как ссылаться и что можно копировать

- В коде и документах ссылайся так: `// OpenD6: adventure p.63 (Wound Levels)`. Это нужно, чтобы следующий агент проверил за секунды.
- Дословный текст, таблицы и списки из книг можно переносить **только** в `src/rules/opend6/` (лицензия OGL, [ADR-0012](../../docs/adr/0012-licensing.md)).
  В `docs/` и остальном коде — пересказ своими словами и ссылки на страницы.
- Не использовать «D6 System» как название или марку (Product Identity). Название «OpenD6» использовать можно.

## Обслуживание индекса

- Добавили PDF: внести запись в `CATALOG` в `scripts/ref/extract.py` (slug, файл, название, приоритет, зачем) и запустить `python3 scripts/ref/extract.py`.
  `INDEX.md` и `text/` пересоберутся, `TOPICS.md` не трогается.
- Сверили правило и нашли в книге более точное место: поправь строку в [TOPICS.md](TOPICS.md).
- Требования: Python 3.10+ и poppler-utils (`pdftotext`, `pdfinfo`, `pdftohtml`, `pdftoppm`). Сторонних Python-пакетов нет.
- PDF лежат в репозитории. Новый PDF больше 50 МиБ не добавлять ([ADR-0014](../../docs/adr/0014-reference-books-in-git.md)).
- Клон без книг (быстро): `git clone --filter=blob:none …` — PDF скачаются только при обращении к ним. Без PDF работают поиск и чтение по `text/`, но не `render`.
